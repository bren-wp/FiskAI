# FiskAI Server

PHP 8.3+ with PDO MySQL, curl and XMLWriter; MySQL/MariaDB with InnoDB. Keep server/ outside the document root; deploy web/ and server/ as sibling directories. Set the web document root to `web/public` only. Configure TLS, database credentials and a random 32+ character FISKAI_PUBLISH_TOKEN via server environment; never commit secrets. Set FISKAI_DB_DSN (mysql:host=...;dbname=...;charset=utf8mb4), FISKAI_DB_USER, FISKAI_DB_PASSWORD. Run `php server/bin/migrate.php` using migration credentials, then use a limited runtime account. Existing 001.sql installations are adopted without deleting data; back up the database first and verify the existing schema matches 001.sql. The runner serializes migrations using a database advisory lock and records SHA-256 checksums. MySQL/MariaDB DDL implicitly commits, so only retry-safe CREATE TABLE IF NOT EXISTS migrations are currently accepted. An interrupted migration is retried using identical SQL; altered or missing recorded migrations are rejected. Non-idempotent migrations require a separately reviewed protocol. This is a single-merchant deployment, not a multi-tenant SaaS.

Run `php server/bin/import-kpd.php` on the server to fetch the official DZS open dataset, validate level 6 and store source hash. The current catalogue is imported only after successful validation. Run after checking for updates; no downloaded data is bundled yet.

POST /api.php?action=publish with JSON and Authorization: Bearer <server token>. Payload: site (stable slug or ZA_SVA_PRODAJNA_MJESTA), kind ROBA/USLUGE, identifier (OIB or matični broj), location (classified location, address, designation; omit for all sites), rows with prescribed fields. Example service row: {"naziv":"Usluga","maloprodajna_cijena":"12.50","poseban_oblik_prodaje":false,"bazna_cijena":"10.00"}. The API writes and publishes synchronously in one transaction. GET /api.php?action=download&site=...&kind=USLUGE&format=csv (or xml) remains stable; version=N opens an archived version for 15 days after replacement. Older rows are retained. The consumer-facing page lists links. No scheduler or Android sync yet; merchant must submit changes by the applicable deadline. Missing anchor values are rejected, not invented. Goods optional fields are supplied by the publisher. Validate applicability, identifier and location semantics, price evidence and field interpretation before production. API token is server-only; no public admin write interface. No personal invoice data is accepted by these APIs.

Sources: NN 132/2026-1584, DZS KPD 2025 open dataset (https://data.gov.hr/ckan/dataset/kpd-2025). XML element names and CSV headers are our implementation, not a claim of official schema certification. Test on both MySQL and MariaDB, with concurrent publication and archive expiry, before deployment. No live deployment performed.


## Izolirana DEMO sinkronizacija (protokol 1)

Nakon migracije 004, administrator za zaseban testni subjekt dodjeljuje UUID i pokreće `php server/bin/demo-sync-device.php provision SUBJECT_UUID`. Izlaz sadrži identitet subjekta, uređaja i jednokratno prikazani token. Prenijeti ga sigurnim kanalom; ne spremati u logove, GitHub ili sigurnosne kopije. Token vrijedi 30 dana, baza čuva samo SHA-256 slučajnog 256-bitnog tokena. Opoziv: `php server/bin/demo-sync-device.php revoke DEVICE_UUID`. Novi token zahtijeva novo provisioniranje i opoziv starog. Identitet uređaja znači identitet izdane vjerodajnice, ne hardversku atestaciju.

Endpoint `POST /api.php?action=demo-sync` je isključen dok administrator ne postavi `FISKAI_DEMO_SYNC_ENABLED=1`. Potreban je HTTPS i pouzdana konfiguracija web servera koja postavlja HTTPS; aplikacija ne vjeruje zaglavljima X-Forwarded-Proto od klijenta. Proslijediti Authorization do PHP-a i ne bilježiti ga u pristupnim logovima. Ograničiti broj zahtjeva na reverse proxyju i pristup administracijskom CLI-ju. Runtime računu dati minimalne ovlasti nad tablicama; provisioniranje/opoziv izvršavati izdvojenim računom.

U izoliranom DEMO APK-u na zaslonu Evidencija naplate odaberite Sinkroniziraj DEMO naplate. Unesite vlastitu pouzdanu HTTPS adresu koja završava s /api.php, UUID subjekta i token. Token nije trajno pohranjen u aplikaciji. Prenose se isključivo odabrani metapodaci nepromjenjivih DEMO alokacija trenutnog lokalnog subjekta, bez imena, OIB-a, napomena ili dokumenata. Koristiti samo sintetičke podatke. Server izvodi opseg iz autentificiranog tokena, ne iz proizvoljnog ID-a klijenta.

Najviše 50 događaja po zahtjevu, 64 KiB, 2000 događaja po subjektu. Identitet događaja i primitka jedinstven je unutar subjekta. Ponovljeni identični zapis potvrđuje se bez ponovnog upisa; promijenjeni zapis ili primitak s drugim identitetom odbija cijeli paket (409). Nema automatskog prepisivanja, brisanja ili korekcije. U slučaju prekida ponoviti ručnu sinkronizaciju istih lokalnih događaja; već potvrđeni paketi ostaju na serveru. Cijeli višepaketni prijenos nije jedna transakcija. Android potvrdu prikazuje samo nakon provjere svih identiteta u odgovoru. Nema trajne lokalne potvrde ni povratne sinkronizacije, server ne verificira stvarni dokument ili ukupnu naplatu i ne koristi zapise za fiskalni outbox. Ovo nije produkcijski multi-tenant sustav, fiskalizacija ili autorizirani prijenos prema CIS-u. Potrebni su produkcijska autentifikacija, sigurnosni audit, politika zadržavanja, backup/restore servera, upravljanje ključevima, provjera stvarnih ovlaštenja i E2E HTTPS test prije šire uporabe.
